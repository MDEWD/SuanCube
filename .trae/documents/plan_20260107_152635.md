# 彻底解决Next.js构建错误的方案

## 问题分析
构建错误是因为项目中仍然包含Umi.js相关依赖，这些依赖依赖于`@umijs/bundler-webpack`，而该包中的LICENSE文件没有合适的loader处理。

## 解决方案

### 1. 移除Umi.js相关依赖
从`package.json`中移除所有Umi.js相关依赖：
- `@umijs/fabric`
- `@umijs/lint`
- `@umijs/max`
- `umi-presets-pro`

### 2. 配置Webpack处理静态文件
在`next.config.js`中添加Webpack配置，使用file-loader或asset/resource来处理所有静态文件：

```javascript
webpack: (config, { isServer }) => {
  config.module = config.module || {};
  config.module.rules = config.module.rules || [];
  
  // 添加规则处理静态文件
  config.module.rules.push({
    test: /\.(txt|md|LICENSE|README)$/i,
    type: 'asset/resource',
    generator: {
      filename: 'static/[hash][ext][query]'
    }
  });
  
  return config;
}
```

### 3. 更新脚本配置
确保`package.json`中的脚本已经完全替换为Next.js命令：
- `dev` -> `next dev`
- `build` -> `next build`
- `start` -> `next start`
- `export` -> `next export`

### 4. 清理缓存
删除`.next`和`node_modules`目录，重新安装依赖：
```bash
rm -rf .next node_modules
npm install
```

## 预期效果
- 移除所有Umi.js相关依赖，避免冲突
- 配置Webpack正确处理所有静态文件
- 解决LICENSE文件的构建错误
- 项目成功构建和运行
